# 发布前全量审计记录

更新时间：2026-09-05。审计范围包括启动恢复、订阅存储、点播/直播链路、IPC、缓存、测试构建和数据目录。

## 结论

当前代码不应直接作为正式发布版。主要阻断项是启动时强制恢复失效订阅会让首页直接显示错误，以及 debug 测试包与正式 bundle 使用相同 macOS bundle identifier 时可能复用旧窗口，造成隔离测试数据被用户看到。

本次已修复启动容错：上次订阅失败后自动尝试最多 6 条其他已保存订阅，全部失败时保留订阅列表，不再把错误伪装成“没有配置源”。

## 数据核查

实际应用数据文件：`~/Library/Application Support/com.iptvmac.desktop/config-store.json`。

审计时该文件包含 42 条订阅，均为原有外部 HTTP/HTTPS 地址；没有发现 `127.0.0.1` 被写入正式配置。`127.0.0.1` 只出现在 `scripts/subscription-test-env.mjs` 创建的 `/var/folders/.../iptv-subscription-test-*` 临时目录。

根因是测试脚本给 debug 进程注入 `IPTV_TEST_DATA_DIR`，而测试包仍使用正式 bundle identifier `com.iptvmac.desktop`。macOS 对同 bundle 的多进程窗口复用不够明显，CUA 可能连接到旧窗口。这是测试隔离缺陷，不是配置删除逻辑，但用户看到的效果确实像订阅被替换。

## 审计结果

| 区域 | 结果 | 说明 |
| --- | --- | --- |
| 配置持久化 | 通过 | 原订阅保存在 `config-store.json`，保存采用临时文件替换 |
| 默认源迁移 | 有风险 | 首次启动会合并内置源；不会覆盖同 URL 的已有项目 |
| 启动恢复 | 已修复 | 失效源自动尝试备用订阅 |
| 点播 | 条件通过 | JSON/XML/type4/多仓和静态网页解析已验证；JAR/CSP、动态嗅探未完成 |
| 直播 | 条件通过 | 聚合、去重、线路请求头、缓存和换线已验证；公网长期稳定性未验证 |
| IPC | 条件通过 | 主要命令有类型封装，但旧 `invoke_ipc` 路由仍并存 |
| 数据库 | 条件通过 | SQLite 迁移和缓存测试通过；历史/收藏尚未纳入订阅身份 |
| 发布工程 | 未通过 | 当前是 debug 包，存在 dead_code 和 Vite 大 chunk 警告，未做签名公证 |

## 必须完成后才能发布

1. 使用独立测试 bundle identifier 或独立应用名称，彻底隔离测试窗口和正式数据目录。
2. 用用户真实订阅做启动恢复、点播首帧、直播持续播放和弱网换线验收。
3. 将历史/收藏主键扩展为订阅身份兼容模型。
4. 对 JAR/CSP、动态网页嗅探和 DRM 做明确产品取舍或阻止导入提示。
5. 完成 release 构建、签名、公证、安装升级和干净机器验收。
