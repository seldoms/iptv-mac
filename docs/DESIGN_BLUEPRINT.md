# 设计蓝图

## 产品目标

把多个点播和直播订阅统一放入一个 macOS 播放器：点播按需加载并播放，直播提前聚合和巡检，用户点击后尽快看到画面。

## 核心流程

### 点播

1. 设置页保存订阅地址，保存不依赖在线预检成功。
2. 顶部订阅选择器切换当前点播配置。
3. 首页展示兼容站点，进入分类、搜索或详情。
4. 点击剧集后调用站点播放接口；必要时进入静态网页解析或解析器链。
5. 播放器显示首帧、错误诊断，并支持线路、上下集和继续观看。

### 直播

1. 所有已保存订阅在后台并发加载 `lives`。
2. 按频道名归一化合并，保留所有独立线路和请求头。
3. 并发测速，按存活状态和延迟排序，写入 SQLite 聚合缓存。
4. 直播页先读缓存；后台刷新通过进度事件增量更新列表。
5. 点击频道优先播放最佳线路，失败自动尝试下一条；用户也可手动换线。

## 关键数据模型

```text
Subscription { url, name, addTime, updateTime }
Vod { siteKey, vod_id, vod_name, vod_play_from, vod_play_url }
Channel { name, category, urls, lines[], bestUrl, latency, epgId }
Line { url, header, alive, latency }
```

约束：CCTV5 与 CCTV5+ 不合并；同 URL 但不同 Cookie/Referer 仍是不同线路；部分源失败不能清空旧快照。

## 体验与性能目标

- 点播不在启动阶段下载所有内容。
- 直播打开页面不等待全量测速，优先展示本地缓存。
- 直播首帧失败在 5 秒级别尝试下一线路，点播解析保留更长超时。
- 网络请求和解析在 Rust 异步任务中执行，避免阻塞窗口。

## 明确边界

当前不承诺完整 drpy/Cat/ESM 运行时、JAR/CSP、动态脚本嗅探、DRM、鉴权 DASH 分片代理和公网所有线路稳定性。
