# 订阅与播放验证

更新：2026-10-01，补充首页站点切换竞态修复与本次验证结果。未提交、未推送、未覆盖系统已安装应用。

## 当前目标与决策

- 所有订阅地址可保存备用；保存、预检、激活分别处理。离线地址不阻止保存。
- 点播按需加载：订阅 → 站点 → 分类/搜索 → 详情/剧集 → 解析 → 软件内播放。
- 直播提前准备：全部已保存订阅 → 后台解析/分类/频道去重 → 独立线路巡检 → 持久缓存。
- 同一频道只显示一项，保留多个播放地址；CCTV5 和 CCTV5+ 不合并。
- 线路身份包含 URL 和请求头，同 URL 不同 Referer/Cookie 仍是不同线路。
- 直播页面先读缓存；巡检不替换正在播放的频道对象。首次无缓存时增量发布频道。
- 默认每 30 分钟巡检；6 个订阅并发下载、16 条线路并发检查。直播首帧超时 5 秒换线。
- 短时网络失败保留上次订阅缓存，不把网络故障当成清空频道的指令。
- 首页站点 tab 使用配置原顺序，后台测速只更新延迟标识，不再动态移动或移除用户正在操作的 tab。
- 首页刷新、站点切换、分类切换使用请求代数校验，旧响应不能覆盖当前站点或当前分类。
- 继续使用 Tauri/Rust/React；本轮不换框架、不做数据库结构迁移。

## 研发会议结论

| 模块 | 发现的断点 | 本轮处理 |
| --- | --- | --- |
| 订阅 | 保存强制激活；异步旧结果覆盖新订阅 | 保存独立命令、前后端请求版本校验 |
| 首页 | 不支持的 JAR 站点也作为可点击源；IPC 字符串错误丢失 | 支持范围筛选、保留真实错误 |
| 点播接口 | 分类/搜索/详情同步堵塞窗口；type 4 播放接口未调用 | 异步命令；type 4 参数、扩展、播放请求补齐 |
| XML | 标准 dl/dd 剧集和同级节点丢失 | quick-xml 结构解析、属性及多线路映射 |
| 多仓 | urls 对象条目遗漏、子配置相对路径归属丢失 | 对象/字符串仓条目、子配置地址规范化、深度上限 |
| 解析 | 第一个解析器失败即退出；鉴权 query 被清空 | 解析器容错、保留参数/请求头、缓存隔离 |
| 播放 | 解析占位符当视频加载；连播绕过解析 | 占位保护、上下集复用播放解析流程、旧请求失效 |
| 直播 | 只展示单源，重复频道；白名单限源、单线路不测、超200条不测 | 全订阅聚合、别名归一、并发逐线路检查、缓存 |
| HLS | 302 后仍按旧目录重写分片 | 使用最终响应 URL 重写 |

## 测试环境

- `scripts/subscription-test-env.mjs` 创建独立 `IPTV_TEST_DATA_DIR`，运行构建后的 debug app。
- 后台刷新使用同一个 `AppState.data_dir`，不会绕过隔离目录写正式数据库。
- JSON/XML/type4/多仓/慢源/故障源由本地 HTTP fixture 提供；视频使用 MDN flower.mp4。
- 直播 fixture 是 M3U 频道列表加测试视频，并非实际 CCTV 节目信号。
- 原生窗口通过 CUA 点击验证，首帧数据来自数据库缓存 `iptv:playback-metrics:v1`。

## 兼容边界与下一阶段

- JAR/CSP 依赖 Android/Java 环境，当前不支持；加载配置成功不等于该站点可播放。
- JS 只修了相对地址、导出名错误及执行限时，尚不是完整 drpy/Cat 运行时。
- 静态网页媒体提取不等于动态网页嗅探；需要执行脚本、验证或 DRM 的页面未实现。
- 历史/收藏主键缺少订阅身份，跨订阅同站点同 ID 仍可能混淆；需单独设计兼容迁移。
- 带鉴权的 DASH 分片代理未补齐；发布基线先以 HTTP JSON/XML/type4、HLS/MP4 为准。
- 线路检查验证 HTTP 响应/清单或媒体特征，不能证明整场直播、所有分片或解码始终正常。
- 尚未完整验证公共直播源的持续播放、弱网切线 P90、整机休眠唤醒、30分钟真实定时触发。
- 最终 release 签名、公证、安装分发与 debug 测试包分开处理。
- 本次原生隔离 harness 未作为有效 UI 验证：debug 包与正式 app 共用 `com.iptvmac.desktop`，macOS 单实例将 fixture 启动接管到现有窗口；需先拆分测试 identifier。
